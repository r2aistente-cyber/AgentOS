One brain, many faces is the wrong model.
Many brains, one manager is AgentOS.

Most agent frameworks give you one process wearing different personas. AgentOS gives every agent a real, separate one: its own directory, its own config.yaml, its own SQLite memory, its own port in the 9000 range — installed wherever you point it, not centralized in one folder.

The Hub — a single FastAPI service on port 8234 — never holds a conversation. It creates agents from a wizard, health-checks them every 15 seconds, restarts what crashes, and streams logs. That's the entire job. Talking to an agent happens directly with that agent's own API.

The result: an agent for your legal practice can't read the files of your marketing bot, even by accident — there's no shared process to leak through.

architecture

One Hub. N independent processes.

The Hub is the only thing that knows every agent exists. Each agent doesn't know the others exist at all.

per agent, not global

Every agent picks its own tools

None of this is set once for the whole system. Each agent is configured independently — a legal analyst and a marketing bot can run different models, different tools, different rules.

Models

Any provider, per agent

Ollama for fully local inference, or OpenAI, Anthropic, and custom endpoints — swapped per agent, not system-wide.

llm.provider: ollama | openai | anthropic | custom
Tools

A real toolbelt

File read/write, shell exec, git, Python, web search and fetch, and its own memory — granted or withheld per agent.
